# Stop Slop: UI Review Scorecard

Review the running interface when possible. If no preview is available, review the code and mark visual checks as **Not verified**.

## Release gates
- [ ] The main user task is understandable and can be completed.
- [ ] Primary and secondary actions are clear and functional.
- [ ] No fabricated content, testimonials, logos, metrics, or claims are presented as real.
- [ ] Essential content remains available at supported viewport sizes.
- [ ] Keyboard access and visible focus are preserved.
- [ ] Text, controls, and states are legible.
- [ ] Critical interaction, validation, loading, empty, and error states work.

## Product fit and hierarchy
- [ ] The interface fits this product and its users.
- [ ] Important information is easy to find.
- [ ] Layout follows the task rather than a generic template.
- [ ] Primary actions are clear without every action competing for attention.

## Restraint and consistency
- [ ] Decorative tags, badges, eyebrows, numbering, and breadcrumbs are absent unless useful.
- [ ] Cards, borders, dividers, icons, pills, radii, and shadows are selective.
- [ ] Colour and typography have consistent roles.
- [ ] No gratuitous gradients, glow, glass effects, textures, or animations.
- [ ] Starter-kit patterns have been adapted to the product.

## Content and credibility
- [ ] Copy is direct, specific, and non-redundant.
- [ ] Labels use language users understand.
- [ ] Charts, data, imagery, and proof are real or labelled illustrative.
- [ ] No vague AI/SaaS clichés replace useful explanations.

## Responsive and accessible
- [ ] Desktop and mobile layouts work at realistic widths.
- [ ] Content reflows without clipping or unintended overflow.
- [ ] Keyboard access, focus, labels, and states work.
- [ ] Contrast, text sizing, and interaction targets are usable.
- [ ] Motion respects reduced-motion preferences.

Score applicable items: 0 = pass, 1 = minor, 2 = major. Fix release-gate failures regardless of score. A total of 7 or more indicates the interface should be reworked.

## Review note
Record what was inspected, viewports reviewed, material issues, justified exceptions, and anything not verified.
